# Neodymium AI Test Showcases

This project contains a set of showcase tests designed to demonstrate the different ways you can define and execute AI-driven browser tests using the Neodymium AI framework.

## Overview of Showcases

### 1. `PostersFullFolderTest.java` (Batch Execution)
**Feature:** Running all tests within a specific data folder.
**Description:** This test uses `@DataFolder("posters_tests")` and calls `Neodymium.ai().execute()`. It will automatically iterate through all supported data files (YAML, JSON, etc.) in the `posters_tests` directory and execute them as separate test runs. This is the standard way to run a large suite of generated or recorded playbooks without writing individual Java methods for each.

### 2. `DataDrivenShowcaseTest.java` (File-Driven Execution)
**Feature:** Driving a single test entirely from a data file.
**Description:** By annotating the class with `@DataFile("posters_tests/searchForProduct.yml")`, this test executes exactly what is defined in the file. The file MUST contain a `steps` variable. It can optionally contain `before`, `after`, and `context` properties which Neodymium will automatically recognize and execute.

### 3. `InlinePromptShowcaseTest.java` (Java-Driven Execution & Fluent API)
**Feature:** Defining steps directly in Java and utilizing the fluent API.
**Description:** This class demonstrates how to run AI tests without external data files.
- **`testWithPromptDirectlyInJava`**: Shows how to use the fluent API (`.before()`, `.after()`, `.systemContext()`, and `.steps()`) to configure the AI agent's execution parameters entirely within code.
- **`testPromptInJavaWithDynamicData`**: Demonstrates injecting dynamic data into the current `TestData` context directly from Java (`Neodymium.getData().put(...)`), allowing the AI to resolve variables like `${dynamicSearchTerm}` seamlessly.

### 4. `HybridPromptShowcaseTest.java` (Hybrid Execution)
**Feature:** Combining inline Java steps with external data files (Data-driven testing).
**Description:** This test uses a `@DataFile` to load variables (e.g., `hybridTestData.json` containing an array of datasets), but defines the actual execution steps in Java. Neodymium automatically resolves placeholders in the Java string (like `${searchTerm}`) using the active data context. Because the user's `hybridTestData.json` contains multiple entries, Neodymium's test runner will automatically execute this hybrid test multiple times, once for each dataset!

### 5. `InteractiveDebugTest.java` (Interactive Execution)
**Feature:** Launching Neodymium AI in Interactive/HUD mode.
**Description:** This test forces the `neodymium.ai.interactive` property to `true`. When executed with an attached `@DataFile`, it will spawn the AI browser and inject the Neodymium HUD overlay. This allows the test developer to step through the steps step-by-step, edit the steps, view data bindings, and manually observe the AI's execution in real-time.

### 6. `RecordVideoTestPOC.java` (Manual Video Recording to AI Script)
**Feature:** Generating AI test scripts from manual user interactions.
**Description:** A proof-of-concept for the video-to-script pipeline. When run, this test opens the browser, injects an AI observer script, and records the session. You manually interact with the site and press "Stop & Generate AI Test". The framework saves your interaction data and the video file, and then automatically invokes the `GeminiVideoAnalyzer` to convert your recorded actions into an executable Neodymium AI data file.

### 7. `ExecuteRecordedVideoTest.java` (Video Replay Execution)
**Feature:** Running the steps generated by the Video Recorder.
**Description:** This test uses `@DataFolder("videoRecordings")` and sequentially replays all AI test steps that were extracted by the `RecordVideoTestPOC` and saved into the `videoRecordings` folder.

## How to use Before/After and System Context

You have two primary ways to utilize `before`, `after`, and `systemContext` capabilities:

1. **Via Test Data Files**: If your test relies on `Neodymium.ai().execute()`, simply define `before`, `after`, and `context` as properties in your JSON/YAML data files. Neodymium will automatically apply them.
2. **Via Fluent API**: If you are writing instructions dynamically in Java, use the fluent builder API before calling `.execute()`:
   ```java
   Neodymium.ai()
       .systemContext("You are testing an e-commerce site.")
       .before("Navigate to https://localhost:8443/")
       .steps("Add a random poster to the cart")
       .after("Clear cookies")
       .execute();
   ```
